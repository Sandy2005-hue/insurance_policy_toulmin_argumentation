# Health Insurance Claim Adjudication via Hybrid RAG & Toulmin Argumentation

A decision-support prototype that reads a free-text health insurance claim, retrieves the relevant clauses from a real policy wording, and writes a structured **Toulmin argument** ending in one of three verdicts: **Claim Approved**, **Claim Denied** or **Needs Human Review**. Every quote in the argument is checked against the retrieved policy text.

> **Educational project.** It is not legal or insurance advice and it is not a final adjudication. It uses one public policy wording and tests only on synthetic claims.

## Why this domain

In health insurance, a rejection has to be explainable and tied to the policy terms. That makes it a good fit for argumentation: the decision (claim), the facts (grounds), the rule applied (warrant), the policy text behind it (backing) and the exceptions (rebuttal) can each be stated and checked. A wrong approval or denial is costly, so the system escalates to a human when a fact the decision depends on is missing.

## How it works

```
Claim text
   |
   v
(optional) Query rewriting: expand into formal policy keywords (Gemini)
   |
   v
Hybrid retrieval, run twice: coverage-oriented and exclusion/waiting-period-oriented
   BM25 (keyword)  +  ChromaDB / all-MiniLM-L6-v2 (dense)  ->  rank interleaving, deduplicated by clause ID, 4 clauses each
   |
   v
Adjudicator (Gemini, temperature 0): five-part Toulmin JSON, using only the retrieved clauses
   |
   v
Citation check: Backing and Rebuttal must appear word for word in the retrieved clauses
   |
   v
Streamlit UI: verdict, argument, citation-check result
```

**Toulmin mapping**

| Toulmin element | In this system |
|---|---|
| Grounds | Facts of the claim |
| Warrant | The policy rule applied |
| Backing | Verbatim policy quote supporting the rule |
| Rebuttal | Verbatim exclusion or waiting-period quote, or "No relevant exclusions found." |
| Claim | Verdict: Approved, Denied or Needs Human Review |
| Qualifier | Omitted by design. Uncertainty is expressed as *Needs Human Review* instead of hedging words |

**Citation check.** It verifies that quoted text exists in the retrieved clauses (and rejects empty, very short or spliced quotes). It does **not** prove that the verdict itself is correct.

## Tech stack

| Layer | Tools |
|---|---|
| Data preparation | Policy wording split into 157 clause-level chunks with IDs; section and clause titles are prepended before embedding |
| Embeddings and vector store | `all-MiniLM-L6-v2` (sentence-transformers), ChromaDB |
| Keyword retrieval | BM25 (`rank_bm25` via LangChain) |
| LLM | Google Gemini via `langchain-google-genai` |
| Orchestration | LangChain |
| UI | Streamlit |

## Setup

Requires Python 3.10+ and a Google AI Studio API key.

```bash
git clone https://github.com/Sandy2005-hue/insurance_policy_toulmin_argumentation.git
cd insurance_policy_toulmin_argumentation
pip install -r requirements.txt
```

Create a `.env` file in the project root:

```
GOOGLE_API_KEY="your_api_key_here"
```

Build the vector store (re-run whenever `data/policy_chunks.json` changes):

```bash
python ingest.py
```

Run the app:

```bash
streamlit run app.py
```

## Limitations

- **One policy.** Only the A PLUS Health Insurance wording, with its separate Policy Schedule unavailable. Plan-dependent values (for example waiting periods "as opted in the Schedule") cannot always be decided and should go to human review.
- **Conflicts in the wording.** Some clauses disagree (for example the maternity waiting period in D.2 versus G.4). The system is instructed to escalate such cases.
- **Synthetic test data.** The test claims are written by hand from the policy text. Results show how well the system follows the policy as written, not how it performs on real claims with bills, discharge summaries and doctors' notes.
- **Small test set.** Results come with wide uncertainty.
- **No partial approvals.** Co-payments, deductibles and sub-limits are not calculated.
- **Citation check scope.** It verifies quotes, not the verdict's correctness.
- **Language models are not deterministic.** Even at temperature 0, outputs can vary between runs and API versions.

## Data and ethics

The policy wording is a public document. All test claims are synthetic, and no personal or patient data is used. The system is intended to assist a human reviewer, who makes the final decision.
